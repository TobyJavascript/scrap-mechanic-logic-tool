Download

Get TobyWand from the Steam Workshop or GitHub: see the download page. Enable it on a creative world, and take TobyWand from your inventory.

Controls

Hold TobyWand and press R to open or close the panel.

KeyWhat it does
Click / dragAdd to the active group / box select (in wire mode: wire parts)
Right clickNext group
F + ClickPick every matching part (by type, colour, gate mode or timer setting)
F + Right clickDelays from that part; again: delays to it; again: off
QSwitch between select and wire mode
Q while box draggingBox select mode: 3D, or one XY, XZ or YZ layer. The next drags keep it
ROpen / close the panel; stops the log viewer and the step debugger

The log viewer and the step debugger keep their controls on the mouse, so you can walk around while using them. See the log and the debug window.

Groups

Everything starts with groups. Click logic parts to add them to the active group (A, B or C), or drag a box around many at once. Right click moves on to the next group.

Order matters. Each part shows its number in the group (A0, A1…), and wiring like zip and chain follows that order. Sort a group by X, Y or Z, or reverse it, to line it up with another.

Wiring

The connect section wires whole groups at once. The mode dropdown, first in the section, picks what the buttons do:

  • Connect adds wires,
  • Cut removes them,
  • Flip toggles each one: wired becomes unwired and the other way round.
ButtonWires
All>AllEvery part of A to every part of B
ZipA0→B0, A1→B1… in group order
ChainThe active group in a line: 0→1→2…
RingA chain that closes the loop, last→first (3 or more parts)
SelfEach part to itself. A self-wired XOR is a memory cell
Clear in / Clear outRemoves every input or output of the active group

Undo reverts the last action, wiring or bulk edit.

Wire click mode

Press Q, or use the dropdown next to the active group, to switch clicks from select to wire. TobyWand then works like the game's connect tool, and every change is logged.

KeyIn wire mode
DragFrom a part to a part: wire them, or cut the wire if they already are (either way round). Letting go on nothing cancels
ClickPick the source, then click the parts it should feed (click a wired part again to cut)
Right clickDrop the source
QBack to select mode

Dots mark the parts you can wire: grey for parts you can pick, yellow for the one you're aiming at, and green for the source. You don't have to hit a part exactly; aiming near its dot is enough.

Groups limit what can be wired. With parts in A, wiring can only start on A. With parts in B, it can only end on B. With both empty, any part with a logic output can be the source and any part with a logic input the target.

The log

Every wire change made with TobyWand goes into the log: buttons, scripts, wire clicks and undos. Each entry says what happened (how many wires were connected and cut) and how long ago.

Open the Log window and press View log to step through the entries in the world. Green arrows are wires that were added, red arrows wires that were removed.

KeyIn the log viewer
Click / Right clickOlder / newer entry
QUndo the entry shown, even if it isn't the last one
RStop

The log follows your parts through bulk edits. Parts removed by hand, or replaced by Build LUT, can't be shown any more, and the entry says so.

Bulk edit

The edit section changes every part in the active group at once:

  • Set gates sets every logic gate to the mode in the dropdown (AND, OR, XOR, NAND, NOR, XNOR).
  • Set timers sets every timer to the delay you type. Write it as ticks, seconds or both: 5t, 2s, 1s 5t. A plain number is ticks.

The creation is rebuilt from its blueprint. It stays on the lift, keeps its wires and your groups, and Undo puts it back as it was.

Debug window

Analysis

  • Timing: the fewest and most ticks from group A (start) to group B (end), and the slowest path.
  • Loops and glitch risks: a glitch risk is a gate whose inputs arrive on different ticks, so it can flicker.
  • Truth table from A (inputs) to B (outputs).
  • Delay probe (F + Right click): numbers every gate by how many ticks it is after, or before, a part.

Step debugger

Start debug runs the logic between A and B one tick at a time, like a code debugger. It works on a copy of the circuit as it is now, so the creation never changes.

  • Arrows show this tick's changes (green on, red off) and wires that stay on (yellow).
  • A countdown over each part says how many ticks until it changes next. Self-wired XOR memories read MEM on / off.
  • Inputs can be a constant input, a 1 tick pulse, a pulse every N ticks, or left free after tick 0.
KeyIn the step debugger
Click / Right clickOne tick forward / back
QRun / pause, at the speed typed in the Debug window (seconds per tick)
RStop

Modules and LUTs

The Module window loads the logic between A (inputs) and B (outputs) as a truth table. Edit the outputs, then Build LUT rebuilds that logic as a clean lookup table: A in a line, inverters, one AND per row, and B as the ORs.

  • You see a ghost preview before anything changes.
  • The old circuit is removed as a whole, or kept whole when something else still uses it. Gates that only feed A move along with it.
  • Afterwards the tool reloads the module and checks it against your table. Undo build puts the creation back.
  • Builds that would go over the game's 255 inputs or outputs per part are refused before anything changes.

Two styles, chosen in Settings:

  • ROM: a decoder and an OR plane.
  • XOR: XORs of shared AND terms (positive-polarity Reed–Muller), often much smaller.
  • Auto picks the one with fewer gates.

Settings also choose stacked or spread-out gates, and even timing (no glitches) or fewer gates.

Lua scripting

The Script window runs Lua against your groups. A, B and C are lists of the parts you selected, in group order, and functions like connect wire them.

-- pair A and B by their position along X
sort(A, "x")
sort(B, "x")
connect(A, B, "zip")

The editor has syntax highlighting, Format (re-indents and refreshes the colours), and a library: save your own scripts by name, next to the built-in examples.

All or nothing. Nothing is wired unless the whole script runs without errors. A finished run is one Undo step and one log entry.

Counting from 0 and 1. In game, parts are numbered from 0 (A0, A1…), but Lua lists start at 1. A[1] is A0, A[2] is A1, and A[#A] is the last one.

Parts

Each item in a group is a table describing one part. Reading these never changes the game.

FieldValue
p.x p.y p.zPosition, in blocks
p.group"A", "B" or "C"
p.indexIts number in the group, from 0 (what the game shows)
p.kind"gate", "timer", "input", "output", or "script" for modded parts with an input and an output
p.modeGates only: "AND" "OR" "XOR" "NAND" "NOR" "XNOR"
p.delayDelay in ticks (1 for a gate, the set delay for a timer)
p.colorPaint colour as hex, like "df7f00"
p.idA unique id, the same for the same part in every group

print(p) prints a part by its name, like A3.

Wiring functions

Wherever a function takes a or b, you can pass one part or a list of parts.

connect(a, b, mode)

Wires a to b. mode is "all" (the default: every part of a to every part of b) or "zip" (a[1]→b[1], a[2]→b[2]…). If zip gets lists of different lengths, it pairs the shorter length and prints a note.

cut(a, b, mode)

Removes wires, paired the same way as connect.

flip(a, b, mode)

Connects each pair that isn't wired, and cuts each pair that is.

chain(list)

list[1]→list[2]→list[3]…

ring(list)

A chain, then the last part to the first. Needs 3 or more parts, since 2 would be a two-way wire, which the game doesn't allow.

selfWire(a)

Wires each part to itself. A self-wired XOR gate holds its state: a memory cell. No other function wires a part to itself; connect(A, A) skips those pairs.

clearInputs(a)  ·  clearOutputs(a)

Removes every input, or every output, of the parts.

List functions

Groups are plain Lua tables, so #A, ipairs(A) and indexing all work as normal.

sort(list, key)

Sorts the list in place and returns it. key is "x", "y", "z", "index" or "delay", with a - in front for descending ("-z"). The default is "x". Parts that tie keep their order. You can also pass a function: sort(A, function(p, q) return p.y < q.y end).

reverse(list)

Reverses the list in place and returns it.

slice(list, i, j)

A new list of items i to j. Negative numbers count from the end: slice(A, 2, -1) is everything but the first.

filter(list, fn)

A new list of the parts where fn(p) is true.

join(a, b, …)

One new list of all the parts given, in order: join(A, B, C[1]).

getbit(n, k)

Bit k of the number n (0 or 1), counting from 0. Handy for decoders.

print(…)

Writes to the script output below the editor. Parts print as their name.

Standard library

Scripts run normal Lua: local, if, for, while, repeat, functions, closures and tables. These are available:

  • math, string, table and bit
  • pairs ipairs next type tostring tonumber select unpack assert error pcall

Scripts can't touch files, the game or other mods: only the wiring functions change anything.

Limits and errors

LimitValue
Wiring operations per run20,000
Printed lines400
Running time2,000,000 steps; past that the script stops as an endless loop

Errors name the line, like line 4: connect needs a part or a list of parts, got nil, and the line is marked in the editor. Use error("message") to stop a script yourself.

Examples

These are in the script library in game too.

Decoder

A holds the input bits (lowest first), C the same bits through NOT gates, and B one AND gate per output value.

for i, gate in ipairs(B) do
    for k = 1, #A do
        if getbit(i - 1, k - 1) == 1 then
            connect(A[k], gate)
        else
            connect(C[k], gate)
        end
    end
end
print("decoder for", #A, "bits,", #B, "outputs")

Shift register / delay line

-- chain A in X order, then feed the last one into B
sort(A, "x")
chain(A)
connect(A[#A], B)

Reverse a bus

-- A[1] -> B[n], A[2] -> B[n-1], ...
for i = 1, math.min(#A, #B) do
    connect(A[i], B[#B + 1 - i])
end

A row of memory cells

-- A = XOR gates (the cells), B = one set line per cell
selfWire(A)
connect(B, A, "zip")

Only some gates

local xors = filter(A, function(p)
    return p.mode == "XOR"
end)
connect(xors, B)
print(#xors, "XOR gates connected")
